# Database migrations

**One owner of the schema:** `python -m app.migrate` (`backend/app/migrate.py`), which runs
Alembic (`backend/alembic/`). The API and the worker never create or alter tables. The database URL
comes from `DATABASE_URL`, the same variable the app uses.

```bash
cd backend
python -m app.migrate            # bring the schema to head (safe to repeat, safe to run concurrently)
python -m app.migrate --check    # report only; exit 1 if the schema isn't current
alembic revision --autogenerate -m "what changed"   # after editing models
alembic check                    # fails if models and migrations drift
```

## Startup order

| Where | How the schema gets migrated |
|---|---|
| `docker compose up -d --build` | `database` (healthy) → `migrate` (one-shot, must exit 0) → `backend` + `worker` (healthy) → `frontend` |
| Without Docker | Run `python -m app.migrate`, then start `uvicorn app.main:app` and `python -m app.worker` |
| `scripts/journey.sh` | Migrates its temporary database before starting the API and worker |
| Hosted | Run `python -m app.migrate` as the release / pre-deploy command, before the new API version starts |

- The API waits up to `GUESTLIFT_SCHEMA_WAIT_SECONDS` (default 120) for the schema to reach the
  version its code expects, then refuses to start with "Run `python -m app.migrate`".
  `/api/ready` returns 503 with the reason whenever the schema is behind.
- The worker waits the same way. If it gives up it exits with code 3; stopping it while it waits
  exits 0.
- Concurrent runs are serialized: a PostgreSQL advisory lock (`pg_advisory_lock(73072026)`) or,
  on SQLite, a `<db file>.migrate.lock` file lock. Later runs report `schema already current`.

## Databases created by older versions

Before P0, the API and worker each built the schema at startup with `create_all()` plus ad-hoc
`ALTER`s. Those databases have no `alembic_version` table. `python -m app.migrate` **adopts them in
place**: it runs every migration from the start, and each one skips what already exists. That fills
in what the old code never added, such as the M4 columns, workspace scoping and the
one-open-sync-job index, without touching existing rows. Duplicate open sync jobs left by the old
race are closed first, keeping the newest.

The output says `adopted a database created by an older version: empty -> <head>`.

Afterwards the database is compared with the models. If a table or column is still missing (the
database was changed outside Alembic), migrate **stops and lists the gaps. It never stamps a
revision it didn't apply.** Restore the database or write a migration for the gaps.

## Rules for new migrations

- **Every migration must be idempotent:** check for the table, column or index before creating
  it, and guard downgrades the same way. `tests/test_schema_lifecycle.py::test_every_migration_can_replay_on_a_current_database`
  replays every `upgrade()` on a current database and fails otherwise.
- Indexes and constraints belong in the models (`__table_args__`) and in a migration, never in
  startup code. `tests/test_service_startup.py::test_application_code_never_changes_the_schema`
  fails if code under `app/` issues DDL.
- Always review autogenerated migrations. Alembic can't detect everything (renames, data migrations).
- Lifecycle coverage: `tests/test_schema_lifecycle.py` (SQLite) and
  `tests/test_postgres_lifecycle.py` (PostgreSQL; set `TEST_POSTGRES_URL` to a server where the test
  may create and drop its own databases). Legacy fixtures in `tests/fixtures/legacy_schemas/` were
  produced by running the old startup code (`scripts/make-legacy-schema-fixtures.sh`).

## Recovering a local stack that won't start (no reset)

Symptoms on versions before P0: the worker in a restart loop with `relation
"uq_square_sync_jobs_one_open" already exists`, the backend exiting with `column
saas_workspaces.trial_started_at does not exist`, or `could not create unique index`.

1. Optional, read-only backup:
   `docker compose exec -T database pg_dump -U guestlift -d guestlift > tablesignal-backup.sql`
2. From a checkout that includes the fix, run `docker compose up -d --build`. The `migrate` service
   adopts the database in place. `docker compose logs migrate` shows what it did.
3. Check with `docker compose ps -a`: `migrate` exited (0), and `backend`, `worker` and `frontend`
   are healthy.

**Never `docker compose down -v`.** It deletes the database volume. To rehearse on a copy first,
restore the backup into a separate project, for example
`TABLESIGNAL_API_PORT=8300 TABLESIGNAL_WEB_PORT=3300 docker compose -p tablesignal-copy up -d database`,
load the backup with `psql`, then run `scripts/compose-smoke.sh` with `SMOKE_PROJECT=tablesignal-copy`.

`scripts/compose-smoke.sh` is the CI `docker` job. It starts a project, waits for every service to be
healthy, checks `/api/ready`, registers and signs in over HTTP, and watches the worker for 30s.
Then it restarts the API and worker and runs `up` again, which must report `schema already current`.

## Revision 0002: workspace scoping of the demo tables

`canonical_orders`, `import_runs`, `campaigns`, `campaign_redemptions` and
`campaign_import_runs` now carry `workspace_id`. Uniqueness that used to be
global (one order per provider and id, one redemption id, one campaign id) is
now per workspace.

- Existing rows are backfilled into the `public-demo` workspace.
- The unauthenticated demo endpoints (behind `GUESTLIFT_ENABLE_DEMO_ENDPOINTS`)
  only ever read and write `public-demo`. Private merchant data lives in the
  tables keyed to `saas_workspaces`, which were already workspace-scoped.
- Local databases created before this revision are adopted by `python -m app.migrate`
  (see above).
- Tested against SQLite and PostgreSQL 16, including adoption of a populated
  database created by the old `create_all()` path.
- **Downgrade deletes rows belonging to any workspace other than
  `public-demo`**, because they could collide once global uniqueness returns.
  Take a backup first if that ever matters.

`tests/test_workspace_scoping.py` fails if a new table is added without a
`workspace_id` column and without an explicit exemption.
